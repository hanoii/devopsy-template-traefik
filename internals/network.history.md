History, not rules: `internals/network.md` wins where they differ.

- The network-scoped name for a sibling: devopsy-template-drupal11's `alwaysup` resolved `app` to another site's app while its own was stopped.
- The socket proxy once allowed `containers/.*`, which also let through `export`, `archive`, `logs` and `attach` of every container.
- Traefik read-only with no capabilities, and no plugins storage for local plugins, was checked on v3.7.13.
- `api_access` was checked on Debian 13 with Docker 29: the host got 200, a container on `traefik` 403. Docker 29 printing a missing gateway as `invalid IP` made the whole router invalid, hence the filter.
- `PROXY_READ_TIMEOUT` exists because Traefik v3's default of 60s cut large uploads, like a registry's layers.
- Projects' own networks replaced one shared network for every routed container, on which a compromised site reached the others past Traefik's middlewares and Docker's DNS answered an alias with any project's container.
- Alternatives set aside for that: devopsy-cli joining by label (proxy behavior in the cli, and a gap at a recreate); `enable_icc=false` on the shared network (it blocks Traefik's own traffic unless Traefik moves to the host network); a compose override listing every network (every release recreates Traefik); a connect step in each project's release (every project must carry it, forgetting means a 30 s hang then a 504, and a Traefik recreate outside `deploy` cuts every site).
- Measured on Docker 29.9.3, Compose 5.7.0 and Traefik v3.7.17 in an OrbStack machine. Traefik's restart, median visitor outage: 2.6 s with 1 site, 5.7 s at 10, 6.3 s at 25, 13.1 s at 50, 33 s at 100, against 3.1 s at 100 on the shared network; its recreate: 2.4 s, 4.7 s, 8.7 s, 11.4 s, 26 s, against 3.7 s. Most of it is `docker stop` on many networks (25 to 38 s at 100), with high variance, and the nftables backend did not help. A project's own release cost the others nothing: every request answered during one, at 1 and at 100 sites.
- `up --no-start`, connecting, then `up` was the first design for a recreate, and was slower than a plain `up` with `attach` reconnecting at every size (4.5 s against 2.4 s at 1 site, 42 s against 26 s at 100).
- Without `gw_priority`, connecting a network that sorts earlier cut in-flight requests through the published port (3 of 3, at 1.18 s).
- `attach` first signalled itself when its event stream ended, which did nothing as PID 1, and it stayed healthy and deaf after `netproxy` was recreated.
- A review found a one-off taken for Traefik, network labels read as fields, a failed read cutting every site, a stopped Traefik unable to start on a network gone or made again, a project's `dockerproxy` answering Traefik's plain name, and the removal beating the next `up` under load (2 of 10 with about 20 tests on 4 lanes, 0 of 40 with fewer).
- Accepted: a change to a project's own network settings needs a down first, since compose disconnects the container before failing on Traefik's endpoint and a rollback's `up` starts it off the network; compose's own `restart` skips the wait for `attach`; forging labels takes the Docker API.
- Traced later on clean machines of the same kind: the real Traefik on 100 sites stopped in about 8 s and started in about 3 s, about 12 s for visitors, so the 25 to 38 s above was not reproduced and its difference is unexplained. It is linear, about 70 ms a network to stop and 28 ms to start, whatever is on the networks and with or without traffic through them. dockerd's `Sandbox.Delete` goes a network at a time, most of it waiting on the kernel in netlink (`LinkSetNsFd` moving the interface out, `LinkDel` deleting it), using little CPU (1.7 s of 10.5 s); iptables took about 4%. Nothing in the template's control shortens it but fewer networks.
- `internal: true` was first on each template's `default`. A real project with a database, moved by a release on compose 5.7.0, showed why not: compose stopped everything and recreated `default`, restarted the unchanged database with `Aliases` empty, the migrations failed on its name, and the previous release's return failed the same way, leaving the site down until `up -d --force-recreate`. The earlier move had been of a project with one service, which is recreated anyway.
- A new `name:` on `default` failed too: compose tries to remove the old network while the app is on it, though the failed release did come back untouched. A new key, `private`, makes compose recreate every service on it, and a rollback finds the old `default` as it left it. The cost is that every service names its networks, and the old `default` stays until removed.
- `attach` first remembered a network to remove by name. A `down` and an `up` inside the 10 seconds made a new network under that name, which the removal then took while compose was creating its containers: `network ... not found` in a run of the suite. So it remembers the id too.
- Measured again with each design on one machine: 13 to 15 s at 100 sites while it was quiet, 29 s in the one run while another machine on the same host was building and testing, which may explain the 25 to 38 s above, though it was only seen once.
- A forwarder per project was tried against `attach`: a small TCP relay on the shared network and the project's `proxy`, with the site off the shared network, and Traefik on no project's network. It needed no `attach` and no Docker write access, and worked on a Traefik without either. Traefik's restart at 100 sites was 3 to 4 s, and a site's hold, websockets, uploads and downloads worked. Against it: a compromised forwarder reaches every other forwarder and through it their sites, Traefik no longer sees a site's health (an unhealthy site keeps its router), 99% of requests at 500 connections took about 600 ms against about 90 ms with socat, and changing `proxy`'s settings passes a release with the site left down, through the same loss of names as above. Only sites off the shared network are protected, so a server gains fully only when none is left on it.
- The owner kept `attach` over the forwarders on 2026-11-04: Traefik on every project's network keeps its health checks and its speed, at the cost of `attach`'s write access through its own socket proxy.
- A third review, the owner's choice past the usual two, found the socket proxies' names broken behind an HTTP proxy: Docker hands containers the operator's settings, a `noProxy` listing `dockerproxy` matches neither `netproxy` nor `dockerproxy.<project>_dockerproxy` (Go matches a name and its subdomains), and `attach` never became healthy, so Traefik never started. `attach` could simply opt out. Traefik could not: `NO_PROXY` in `environment:` replaces the operator's list, which holds its exceptions for reaching sites, so the names became a documented step.
- The same review found the wait running from a network's first leave, a failed connect never tried again, and a failed read losing a removal. Keeping removals across a restart would have taken a volume, or removing any empty network of a compose project at start, more power for an empty network the next `down` removes anyway, so it was accepted.
- First run through a real Cloudflare Tunnel: Compose 5.6.1, Docker 29.9.2, a project with a database moved by a release, one left on the shared network beside it. Visitors' addresses and `https` arrived, and neither project reached the other.
- The temporary file for `mnt/dynamic/` first moved out of that folder, on a guess: Traefik's API answered 404 for about 2 s right after `api_access` rewrote its file, on 2 of 315 writes with the file inside and 0 of 315 outside, too few to say. Traefik's source then ruled the guess out, since it skips a `.tmp` file. The cause is the listing: Traefik's file provider lists the folder on every change, and a listing during a rename over a name can miss that name, on btrfs and on overlay over btrfs (thousands of misses in 8 s), never on ext4 or XFS (none in about a million reads each). The missed file's routers go until the next read, one throttle later, which is the 2 s. Each `.yaml` is hence a link that stays put, to a `.live` file Traefik skips, and only that is renamed over. A forced comparison on real Traefik is in the commit that made it.
